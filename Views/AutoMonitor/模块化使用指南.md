# 自动盯盘模块化使用指南

## 模块化重构完成情况

### ✅ 已完成的模块

1. **数据模型层**
   - `AutoMonitorDataModel.cs` - 主要数据模型，包含所有数据绑定属性
   - `UIStateModel.cs` - UI状态管理模型，管理界面状态和样式

2. **业务逻辑层**
   - `AutoMonitorController.cs` - 主控制器，协调各模块工作
   - `TimerController.cs` - 定时器控制器，管理所有定时任务

3. **服务层**
   - `LoggingService.cs` - 专门的日志服务，处理所有日志操作

4. **UI组件层**
   - `UIComponentManager.cs` - UI组件管理器，负责创建和管理UI组件

5. **重构示例**
   - `AutoMonitorDashboard_Refactored.cs` - 重构后的主窗口示例

## 模块化架构优势

### 1. 代码可维护性
- 原始文件: 2930行，所有功能混在一起
- 重构后: 每个模块200-400行，职责明确

### 2. 测试能力
- 每个模块可以独立测试
- 依赖注入使得单元测试更容易

### 3. 可扩展性
- 新功能可以独立开发
- 模块间解耦，修改影响范围小

### 4. 代码复用
- 模块可以在其他项目中复用
- 组件化设计便于维护

## 使用方法

### 1. 基本使用

```csharp
// 创建数据模型
var dataModel = new AutoMonitorDataModel();
var uiStateModel = new UIStateModel();

// 创建控制器
var controller = new AutoMonitorController(
    autoMonitorService, 
    logger, 
    dataModel, 
    uiStateModel);

// 创建UI管理器
var uiManager = new UIComponentManager(dataModel, uiStateModel, logger);

// 初始化UI组件
uiManager.InitializeComponents(this);
var mainLayout = uiManager.CreateMainLayout();
Content = mainLayout;
```

### 2. 启动监控

```csharp
// 使用控制器启动监控
var success = await controller.StartMonitoringAsync();
if (success)
{
    // 监控启动成功
    controller.TimerController.StartAllTimers();
}
```

### 3. 处理事件

```csharp
// 设置事件处理
controller.TimerController.DataRefreshRequested += OnDataRefreshRequested;
uiManager.ToggleMonitoringRequested += OnToggleMonitoringRequested;
```

### 4. 数据绑定

```csharp
// 数据绑定到UI
DataContext = dataModel;  // 数据绑定
// 或者
DataContext = uiStateModel;  // UI状态绑定
```

## 迁移指南

### 第1步：保留原始文件
```
备份原始文件为 AutoMonitorDashboard_Original.xaml.cs
```

### 第2步：创建新的模块化版本
```csharp
// 替换原始构造函数
public AutoMonitorDashboard(AutoMonitorService autoMonitorService, ILogger logger, MainViewModel mainViewModel = null)
{
    // 创建模块
    _dataModel = new AutoMonitorDataModel();
    _uiStateModel = new UIStateModel();
    _controller = new AutoMonitorController(autoMonitorService, logger, _dataModel, _uiStateModel);
    _uiManager = new UIComponentManager(_dataModel, _uiStateModel, logger);
    
    // 初始化
    InitializeModularComponents();
}
```

### 第3步：迁移数据属性
```csharp
// 原始代码
private string _monitorStatus = "未启动";
public string MonitorStatus
{
    get => _monitorStatus;
    set { _monitorStatus = value; OnPropertyChanged(); }
}

// 迁移后
public string MonitorStatus => _dataModel.MonitorStatus;
// 或者直接绑定到 _dataModel
```

### 第4步：迁移业务逻辑
```csharp
// 原始代码
private async void OnToggleMonitoring()
{
    // 复杂的业务逻辑...
}

// 迁移后
private async void OnToggleMonitoring()
{
    await _controller.ToggleMonitoringAsync();
}
```

### 第5步：迁移UI创建
```csharp
// 原始代码
private void CreateUI()
{
    // 大量UI创建代码...
}

// 迁移后
private void CreateUI()
{
    _uiManager.InitializeComponents(this);
    var layout = _uiManager.CreateMainLayout();
    Content = layout;
}
```

## 故障排除

### 1. 模块初始化失败
检查依赖注入是否正确：
```csharp
if (autoMonitorService == null)
    throw new ArgumentNullException(nameof(autoMonitorService));
```

### 2. 事件处理异常
添加异常处理：
```csharp
try
{
    await controller.StartMonitoringAsync();
}
catch (Exception ex)
{
    logger.LogError(ex, "启动监控失败");
}
```

### 3. UI更新异常
确保在UI线程上更新：
```csharp
Dispatcher.Invoke(() => uiManager.UpdateAllComponents());
```

## 最佳实践

1. **单一职责原则**：每个模块只负责一个功能
2. **依赖注入**：通过构造函数注入依赖
3. **异常处理**：每个模块都要有完善的异常处理
4. **日志记录**：关键操作都要记录日志
5. **资源释放**：实现IDisposable接口
