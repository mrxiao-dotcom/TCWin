# 推仓触发失败诊断工具

## 🚨 问题描述
**症状**: 除了第一次推仓外，后续扫描时即使浮盈超过了3阶梯条件，系统也不会执行推仓操作。

## 🔍 快速诊断步骤

### 步骤1：启用超详细日志
1. 重新启动自动盯盘
2. 观察日志中的 `🔧 === 开始超级详细调试 ===` 部分
3. 检查每个阶梯的状态信息

### 步骤3：问题诊断清单

检查每个可能的问题点：

#### ❌ 问题A：推仓配置问题
**症状**: 日志显示 `启用=False`
**解决**: 
1. 打开自动盯盘配置
2. 检查推仓阶梯是否全部启用
3. 保存配置重启盯盘

#### ❌ 问题B：触发金额设置过高
**症状**: 日志显示 `浮盈足够=False`
**解决**:
1. 检查各阶梯的触发金额是否合理
2. 当前浮盈 150U，但阶梯2设置为 200U 就不会触发

#### ❌ 问题C：状态管理错误
**症状**: 日志显示 `已执行=True` 但实际没有执行过
**解决**:
1. 在监控面板找到该合约
2. 点击"清理状态"按钮
3. 选择清理推仓状态
4. 重新测试

#### ❌ 问题D：冷却期卡住
**症状**: 日志显示 `冷却剩余=55.0秒`（接近60秒）
**解决**:
1. 这说明还在使用旧的60秒冷却期
2. 重新编译程序
3. 重启应用

#### ❌ 问题E：浮盈数据不准确
**症状**: 界面显示浮盈150U，但日志显示当前浮盈0U
**解决**:
1. 检查API连接状态
2. 刷新持仓数据
3. 重新连接API

## 🛠️ 临时解决方案

### 方案1：重置状态
```
1. 停止自动盯盘
2. 在监控面板中清理该合约的所有状态
3. 重新启动自动盯盘
4. 观察是否正常触发
```

### 方案2：重启应用
```
1. 完全关闭程序
2. 重新启动程序
3. 重新配置自动盯盘
4. 测试推仓功能
```

### 方案3：手动验证配置
```
1. 记录当前持仓的浮盈数值
2. 在自动盯盘配置中设置一个很低的触发金额（如10U）
3. 启动盯盘观察是否立即触发
4. 如果触发正常，则逐步调整到实际需要的金额
```

## 📊 日志分析要点

关键要看这几个字段的组合：
- `启用=True` ✅
- `浮盈足够=True` ✅  
- `已执行=False` ✅
- `冷却剩余=0.0秒` ✅

如果这四个条件都满足，但仍然没有执行，则说明代码逻辑有问题。
