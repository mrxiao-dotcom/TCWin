## 🔄 **工作流程**

### **1. 配置模板管理**
```
用户 → 模板编辑器 → BaseConfigManager → AutoMonitorConfigs.json
```

### **2. 生成统一状态**
```
持仓数据 + 基础配置模板 → ContractMonitoringStateGenerator → contract_monitoring_states.json
```

### **3. 配置切换**
```
用户选择新配置 → SwitchContractConfiguration() → 
从基础模板读取新配置 → 更新统一状态文件（保留执行状态）
```

### **4. 执行状态跟踪**
```
执行引擎 ↔ contract_monitoring_states.json ↔ UI显示
```

## 🛠️ **核心服务**

### **1. BaseConfigManager**
- **文件**：`AutoMonitorConfigs.json`
- **职责**：管理基础配置模板
- **方法**：
  - `LoadConfigurations()` - 加载配置模板
  - `SaveConfiguration()` - 保存配置模板
  - `CreateConfiguration()` - 创建新模板
  - `DeleteConfiguration()` - 删除模板

### **2. ContractMonitoringStateService**
- **文件**：`contract_monitoring_states.json`
- **职责**：管理统一状态文件
- **方法**：
  - `GenerateMonitoringStatesFromPositions()` - 从持仓生成状态
  - `SwitchContractConfiguration()` - 切换单个合约配置
  - `SwitchAllContractsConfiguration()` - 批量切换配置
  - `UpdateExecutionStatus()` - 更新执行状态
  - `IsExecuted()` - 检查执行状态

### **3. ContractMonitoringStateGenerator**
- **职责**：状态生成逻辑
- **方法**：
  - `GenerateMonitoringState()` - 从基础配置生成状态
  - `UpdateExecutionStatus()` - 更新执行状态
  - `IsExecuted()` - 检查执行状态

## 📊 **关键特性**

### **✅ 职责明确**
- **基础配置**：模板存储，只能在编辑器中修改
- **统一状态**：运行时状态，包含完整配置+执行状态

### **✅ 数据同步**
- 配置切换时自动从基础模板同步
- 保留现有的执行状态
- 支持单个合约或批量切换

### **✅ 状态完整**
- 每个合约包含完整的配置数据副本
- 每个阶梯都有独立的执行状态字段
- 避免频繁读取基础配置文件

### **✅ 使用示例**

#### **切换单个合约配置**
```csharp
// 将 BTCUSDT_LONG 切换到"狂飙"配置
stateService.SwitchContractConfiguration("BTCUSDT_LONG", "狂飙");
```

#### **批量切换所有合约**
```csharp
// 将所有活跃合约切换到"稳健"配置
stateService.SwitchAllContractsConfiguration("稳健");
```

#### **检查执行状态**
```csharp
// 检查保本是否已执行
bool isBreakEvenExecuted = stateService.IsExecuted("BTCUSDT_LONG", "BreakEven");

// 检查推仓第1阶是否已执行
bool isTier1Executed = stateService.IsExecuted("BTCUSDT_LONG", "AddPosition", 1);
```
