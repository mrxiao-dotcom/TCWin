# 🔧 编辑状态互相篡改问题根本修复

## 📋 问题描述

**用户反馈**：
> "双击配置修改，我发现还是会互相篡改，修改了保本的状态，推仓的状态也变了。我相信是改动流程的问题：应该统一，先改文件，再同步界面。点击保存的时候，根据界面配置改动文件，然后界面再从文件读取。"

## 🔍 根本原因分析

### 🚨 **多重数据源冲突**

发现问题的根源是**`EnsureLatestManualStatus`方法**引入了额外的数据源：

```csharp
// ❌ 错误的流程（修复前）
private ContractConfigViewModel EnsureLatestManualStatus(ContractConfigViewModel originalConfig)
{
    // 从另一个文件 ContractConfigs.json 读取状态
    var savedConfigs = JsonSerializer.Deserialize<Dictionary<string, ContractConfigData>>(json);
    if (savedConfigs.TryGetValue(originalConfig.ContractName, out var savedConfig)) {
        originalConfig.BreakEvenStatus = savedConfig.BreakEvenStatus; // ❌ 篡改UI状态
        originalConfig.SetDynamicData("Push1", savedConfig.PushTier1Status, "Black", true); // ❌ 篡改推仓状态
    }
}
```

### 🔄 **错误的数据流向**

**修复前的混乱流程**：
```
1. UI显示状态A（来自统一状态文件）
   ↓
2. EnsureLatestManualStatus从ContractConfigs.json读取状态B
   ↓
3. 篡改UI对象，显示混合状态C
   ↓
4. 用户编辑混合状态C，保存状态D
   ↓
5. 保存到统一状态文件
   ↓
6. 从统一状态文件重新加载，可能显示状态E
   ↓
7. 结果：用户修改保本，推仓状态被连带篡改 ❌
```

## ✅ 完整解决方案

### **核心修复策略：统一数据源流程**

按照用户建议，实现真正的统一数据源流程：
1. **先改文件**（根据界面配置改动文件）
2. **再同步界面**（界面从文件读取）

### **关键修复1：移除数据源干扰**

```csharp
// ❌ 修复前：从多个数据源获取状态
var configForEditing = EnsureLatestManualStatus(selectedConfig);
var editWindow = new ContractConfigEditDialog(configForEditing, _currentConfig, _logger);

// ✅ 修复后：直接使用当前UI显示的状态
AddLog($"🔧 准备编辑配置，使用当前UI显示的状态 - 保本: {selectedConfig.BreakEvenStatus}");
AddLog($"🔧 确保编辑前后数据源一致：UI显示状态 → 编辑 → 保存到统一状态文件 → 从统一状态文件重新加载");
var editWindow = new ContractConfigEditDialog(selectedConfig, _currentConfig, _logger);
```

### **关键修复2：精确字段更新**

在`SaveContractConfigToFile`方法中，修改为只更新`_editedConfig`中的值，而不是遍历UI控件：

```csharp
// ❌ 修复前：遍历所有UI控件，可能篡改无关状态
for (int i = 0; i < _pushTierComboBoxes.Count; i++) {
    var status = GetComboBoxSelection(comboBox); // 可能读取错误状态

// ✅ 修复后：只更新_editedConfig中的值

```

## 🎯 **新的正确流程**

### **✅ 统一数据源流程（修复后）**：

```
1. UI显示当前状态（来自统一状态文件）
   ↓
2. 用户双击编辑，直接基于当前UI状态
   ↓
3. 用户修改特定字段（如保本状态）
   ↓
4. 保存时只更新用户实际修改的字段到统一状态文件
   ↓
5. 保存完成后，UI从统一状态文件重新加载
   ↓
6. 结果：只有用户修改的字段发生变化，其他字段保持不变 ✅
```

## 🎉 核心改进总结

### **✅ 数据源统一**
- 移除了`EnsureLatestManualStatus`的多数据源干扰
- 编辑对话框直接基于当前UI显示的状态
- 保存后严格从统一状态文件重新加载

- 不再遍历UI控件获取状态
- 只更新`_editedConfig`中用户实际修改的值
- 变化检测机制确保无变化的字段不被触动

### **✅ 流程一致性**
- **编辑前**：基于当前UI状态
- **保存时**：只更新修改的字段到统一状态文件
- **保存后**：UI只从统一状态文件重新读取
