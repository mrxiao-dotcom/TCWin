# ✅ 修复重置功能配置重载问题

## 问题描述
用户反馈"全部重置"功能存在问题：
- 重置功能没有把保本、加仓、止盈的配置按照基础配置来进行重置
- 现有的重置功能只重置执行状态，不会重新加载基础配置的触发价格、保护金额等参数
- 对于已存在的条件，参数没有更新，仍然是旧的配置

## 修复方案

### 核心问题分析
原来的`ReloadContractFromBaseConfig`方法只会：
- ✅ 添加缺失的条件（新增功能）
- ❌ 更新已存在条件的参数（缺失功能）← **这是问题所在**

### 修复实施

#### 1. 增强保本条件重载 
**修复前**：只新增缺失的保本条件
```csharp
// 旧代码只处理新增情况
if (breakEvenCondition == null)
{
    // 新增保本条件
}
// 缺少对已存在条件的参数更新
```

**修复后**：既新增缺失条件，也更新已存在条件的参数
```csharp
if (breakEvenCondition == null)
{
    // 新增保本条件
}
else
{
    // 🔧 更新已存在的保本条件参数
    var oldTriggerPrice = breakEvenCondition.TriggerPrice;
    breakEvenCondition.TriggerPrice = baseConfig.BreakEvenConfig.TriggerProfitAmount;
    breakEvenCondition.KeepValue = 0;
    breakEvenCondition.Description = $"保本条件 - 浮盈{baseConfig.BreakEvenConfig.TriggerProfitAmount:F0}U";
    // 记录更新日志
}
```

#### 2. 增强加仓条件重载
**修复前**：只新增缺失的加仓条件
**修复后**：既新增缺失条件，也更新已存在条件的参数
```csharp

{
    // 🔧 更新已存在的推仓条件参数

```

## 修复效果

### 修复前的问题
- 用户点击"全部重置"后，已存在的条件参数没有更新
- 保本触发价格、加仓触发价格、止盈触发价格和保护金额都保持旧值
- 用户需要手动编辑每个条件才能应用新的基础配置

### 修复后的效果
- ✅ **智能新增**：自动添加基础配置中新增的条件
- ✅ **智能更新**：自动更新已存在条件的所有参数
- ✅ **智能移除**：自动移除基础配置中不存在的条件
- ✅ **详细日志**：记录所有新增、更新、移除操作
- ✅ **参数同步**：确保所有参数都与基础配置保持一致

## 操作流程
1. 用户点击"全部重置"按钮
2. 系统获取当前基础配置
3. 对每个合约执行：
   - 重置执行状态（原有功能）
   - 更新触发价格（原有功能）
   - **🆕 智能重载配置**（新增功能）
     - 保本条件：新增缺失 + 更新已存在的触发价格
     - 加仓条件：新增缺失 + 更新已存在的触发价格、倍数
     - 止盈条件：新增缺失 + 更新已存在的触发价格、保护金额
4. 保存配置到本地文件
5. 显示详细的操作结果
