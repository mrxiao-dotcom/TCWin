# 主窗口关闭监控窗口残留问题修复说明

## 问题描述
用户反映：主窗口关闭后，监控窗口仍然残留在桌面上，没有跟随主窗口一起关闭。

## 问题原因分析

### 根本原因
监控窗口是作为独立窗口创建的，没有与主窗口建立父子关系，导致主窗口关闭时监控窗口不会自动关闭。

### 问题定位
1. **监控窗口创建位置**：`ViewModels/MainViewModel.AutoMonitor.cs` 的 `ShowAutoMonitorDashboard` 方法
2. **问题代码**：
   ```csharp
   var monitorDashboard = new AutoMonitorDashboard(_autoMonitorService, _logger);
   monitorDashboard.Show();  // 独立窗口，没有设置Owner
   ```
3. **缺失的关联**：没有设置 `Owner` 属性，导致窗口生命周期不受主窗口控制

## 修复方案

### 方案1：设置窗口Owner关系
在创建监控窗口时，将主窗口设置为其Owner，确保主窗口关闭时子窗口自动关闭。

**修改文件**：`ViewModels/MainViewModel.AutoMonitor.cs`

**修改内容**：
```csharp
// 创建并显示监控面板（使用简化的构造函数）
var monitorDashboard = new AutoMonitorDashboard(
    _autoMonitorService, 
    _logger);

// 🔧 修复：设置主窗口为监控窗口的Owner，确保主窗口关闭时监控窗口也会关闭
if (Application.Current?.MainWindow != null)
{
    monitorDashboard.Owner = Application.Current.MainWindow;
    _logger.LogInformation("✅ 监控窗口已设置主窗口为Owner");
}
else
{
    _logger.LogWarning("⚠️ 无法获取主窗口引用，监控窗口可能不会跟随主窗口关闭");
}

_logger.LogInformation("🖥️ 监控面板创建成功，使用简化模式");
monitorDashboard.Show();
```

### 方案2：主窗口关闭时手动关闭子窗口
在主窗口的清理方法中，添加关闭所有子窗口的逻辑作为双重保障。

**修改文件**：`ViewModels/MainViewModel.Core.cs`

**修改内容**：
1. **添加using声明**：
   ```csharp
   using System.Windows;
   ```

2. **增强Cleanup方法**：
   ```csharp
   public void Cleanup()
   {
       try
       {
           StopTimers();
           
           // 移除所有订单的选择状态监听，避免内存泄漏
           foreach (var order in Orders)
           {
               order.SelectionChanged -= OnOrderSelectionChanged;
           }
           // ... 其他清理代码
           
           // 🔧 新增：关闭所有相关的子窗口（监控窗口等）
           CloseAllChildWindows();
           
           _logger.LogInformation("MainViewModel清理完成");
       }
       catch (Exception ex)
       {
           _logger.LogError(ex, "MainViewModel清理失败");
       }
   }
   ```

3. **新增关闭子窗口方法**：
   ```csharp
   /// <summary>
   /// 关闭所有子窗口
   /// </summary>
   private void CloseAllChildWindows()
   {
       try
       {
           if (Application.Current?.Windows != null)
           {
               var childWindows = new List<Window>();
               
               // 收集需要关闭的子窗口
               foreach (Window window in Application.Current.Windows)
               {
                   // 跳过主窗口
                   if (window == Application.Current.MainWindow)
                       continue;
                       
                   // 关闭监控窗口和其他子窗口
                   if (window is Views.AutoMonitorDashboard || 
                       window.Owner == Application.Current.MainWindow)
                   {
                       childWindows.Add(window);
                   }
               }
               
               // 关闭收集到的子窗口
               foreach (var window in childWindows)
               {
                   try
                   {
                       _logger.LogInformation($"🔧 正在关闭子窗口: {window.Title}");
                       window.Close();
                   }
                   catch (Exception ex)
                   {
                       _logger.LogWarning(ex, $"⚠️ 关闭子窗口失败: {window.Title}");
                   }
               }
               
               if (childWindows.Any())
               {
                   _logger.LogInformation($"✅ 已关闭 {childWindows.Count} 个子窗口");
               }
           }
       }
       catch (Exception ex)
       {
           _logger.LogError(ex, "❌ 关闭子窗口时发生错误");
       }
   }
   ```

## 修复效果

### 1. 自动关闭机制
- 设置Owner关系后，主窗口关闭时监控窗口会自动关闭
- 符合WPF标准的父子窗口管理模式

### 2. 双重保障
- 即使Owner关系在某些情况下失效，手动关闭逻辑也会确保子窗口被正确关闭
- 避免资源泄漏和残留窗口问题

### 3. 日志记录
- 详细记录窗口关闭过程
- 便于问题排查和调试

## 技术要点

### WPF窗口生命周期管理
1. **Owner属性**：设置窗口的拥有者，子窗口会跟随父窗口的生命周期
2. **Window.Show() vs ShowDialog()**：Show()创建无模态窗口，ShowDialog()创建模态窗口
3. **Application.Current.Windows**：获取当前应用程序的所有窗口集合

### 最佳实践
1. **子窗口必须设置Owner**：确保窗口层次结构正确
2. **资源清理**：主窗口关闭时主动清理所有子窗口
3. **异常处理**：窗口操作需要适当的异常处理
