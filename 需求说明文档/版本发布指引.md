## 🛠️ 发布流程

### 步骤1：选择发布方式

#### 方式A：基础编译 (dotnet build)
```bash
# 清理旧编译文件
dotnet clean

# Release模式编译
dotnet build --configuration Release
```
**适用场景**：开发测试、本地调试
**输出位置**：`bin\Release\net6.0-windows\`

#### 方式B：专业发布 (dotnet publish) ⭐ **推荐**
```bash
# 专业发布 (等同于VS2022发布功能)
dotnet publish --configuration Release --runtime win-x64 --self-contained false
```
**适用场景**：生产部署、服务器发布
**输出位置**：`bin\Release\net6.0-windows\publish\`
**VS2022等效**：完全等同于Visual Studio 2022的"发布"功能

#### VS2022 发布功能对比
| 特性 | dotnet build | dotnet publish (VS2022发布) |
|------|-------------|---------------------------|
| 用途 | 开发调试 | 生产部署 ⭐ |
| 性能优化 | 基础 | 高级优化 |
| 依赖处理 | 基本 | 完整包含 |
| 部署就绪 | 需要配置 | 即开即用 |
| 文件组织 | 开发结构 | 部署结构 |

## 🚀 服务器部署流程

### 1. 停止旧版本
在服务器上：
1. 关闭正在运行的TCWin程序
2. 备份当前版本文件夹
3. 备份配置文件和数据文件

### 2. 部署新版本
1. 上传新版本发布包到服务器
2. 解压到目标目录
3. 恢复配置文件：
   - `appsettings.json`
   - 数据存储文件（如果有）

### 3. 验证部署
1. 运行`VerifyNewVersion.bat`验证程序正常
2. 启动程序检查界面和功能
3. 查看日志确认调试信息正常显示

## 🔍 版本验证要点

### 关键标志确认
新版本必须包含以下标志才算成功：

1. **调试日志标志**：
   ```
   🔧 === 开始超级详细调试 ===
   🔧 阶梯X完整状态: 启用=True, 触发金额=X.XU...
   ```

2. **监控面板标志**：
   - 有`🧹 清理状态`按钮
   - 标题栏动态更新：`🔍 自动盯盘监控面板 - 🟢运行中 | 14:30:25 | 下次扫描: 15秒`

3. **文件大小验证**：
   - `BinanceFuturesTrader.dll` 约800KB
   - `BinanceFuturesTrader.exe` 约166KB

### 功能验证测试
1. **重启测试**：重启程序确认不会重复推仓
2. **状态清理测试**：点击🧹清理状态按钮确认功能正常
3. **冷却期测试**：确认推仓间隔为5秒而不是60秒
4. **多阶梯测试**：确认多个阶梯能按顺序执行

## ⚠️ 常见问题处理

### 编码问题
- 确保所有中文文件使用UTF-8编码
- 避免在批处理文件名中使用中文
- 发布包文件夹使用英文命名

### 依赖问题  
- 确保所有.dll文件都包含在发布包中
- 检查.NET运行时版本兼容性
- 服务器环境确保有.NET 6.0运行时

### 版本混乱问题
- 每次发布前清理bin和obj文件夹
- 确认运行的是最新编译的版本
- 使用版本验证脚本确认版本正确性
