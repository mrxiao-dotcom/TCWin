```

## 📊 详细时序分解

### 第1阶段: 定时器触发 (0-1秒)
```
00:00  ⏰ Timer.Elapsed 事件触发
00:00  🔍 检查服务运行状态 (IsRunning = true)
00:01  📝 日志: "⏰ 定时器触发，开始扫描"
```

### 第2阶段: 文件锁定 (1-2秒)
```
00:01  🔒 await _fileLock.WaitAsync()
00:01  📝 日志: "🔒 [FILE-LOCK] 文件锁定成功"
00:02  📖 LoadStatesFromFileAsync()
00:02  📝 日志: "🔒 [FILE-READ] 从文件加载 X 个合约状态"
```

### 第3阶段: 数据获取 (2-5秒)
```
00:02  📡 调用币安API: GET /fapi/v2/positionRisk
00:03  📊 解析持仓数据
00:04  🔍 生成活跃合约键: ["BTCUSDT_LONG", "ETHUSDT_LONG"]
00:05  📝 日志: "📊 [SCAN-POSITIONS] 当前活跃持仓: 2个"
```

### 第4阶段: 状态处理 (5-15秒)
```
00:05  🧹 CleanupClosedPositions() - 清理已平仓合约

00:07  🔄 开始处理 BTCUSDT_LONG:
00:07    📋 GetContractConfigAsync("BTCUSDT_LONG")
00:08    🛡️ 保本检查: 浮盈95U >= 触发95U → 执行保本

00:11    💰 保盈检查: 3个阶梯检查完成

### 第7阶段: 等待下次循环 (25-30秒)
```
00:25  ⏱️ 等待下一个定时器间隔

00:30  ⏰ 下一次定时器触发 → 回到第1阶段
```

## 🔄 循环特点

### ⚡ 性能优化
- **并行处理**: 多个合约同时检查条件
- **智能跳过**: 无配置或未触发的合约快速跳过
- **批量保存**: 所有状态变更一次性保存
- **异步UI**: UI更新不阻塞主扫描流程

### 🛡️ 容错机制
- **异常隔离**: 单个合约异常不影响其他合约
- **自动重试**: API调用失败时的重试机制
- **状态恢复**: 文件锁定确保状态不丢失
- **日志记录**: 详细的执行日志便于问题追踪

### 📊 监控指标
```
每次扫描的关键指标:
├── 扫描耗时: 通常 3-8秒
├── 处理合约数: 等于实际持仓数
├── 执行操作数: 0-N (根据触发条件)
├── 文件锁定时间: 通常 2-5秒
└── UI刷新时间: 通常 1-2秒
```

## 🎯 关键观察点

启动自动盯盘后，您应该观察：

1. **日志时序**: 确认每个阶段按时执行
2. **文件锁定**: 查看 `[FILE-LOCK]` 相关日志
3. **状态一致性**: 界面显示与文件内容同步
4. **处理效率**: 扫描耗时在合理范围内
5. **执行准确性**: 触发条件与实际执行匹配
