# 合约配置文件优化方案

## 🚨 问题分析

您说得完全正确！当前系统存在以下问题：

### 📁 文件重复问题
```
当前状态 (❌ 重复):
├── contract_configs.json              // 合约具体配置和状态  
├── contract_monitoring_states.json    // 实时监控状态
├── position_profiles.json             // 持仓档案状态
└── execution_history.json             // 执行历史

问题:
- contract_configs.json 和 contract_monitoring_states.json 内容重复
- 维护两套相似的文件，容易造成状态不一致
- 界面呈现数据来源不明确，可能从两个文件读取不同数据
```

## ✅ 优化方案

### 📁 简化文件结构
```
优化后 (✅ 统一):
├── contract_monitoring_states.json    // 📍 唯一的合约状态文件
├── AutoMonitorConfigs.json           // 基础配置模板
├── execution_history.json            // 执行历史（保留）
└── [删除] contract_configs.json      // ❌ 删除重复文件
└── [删除] position_profiles.json     // ❌ 删除重复文件
```

### 🎯 核心设计原则

#### 1. 单一数据源
```
所有合约配置和状态 → contract_monitoring_states.json
所有界面呈现 → 从 contract_monitoring_states.json 读取
所有状态更新 → 写入 contract_monitoring_states.json
```

#### 2. 自动持仓管理
```
新开仓 → 自动检测 → 基于当前基础配置生成状态 → 写入文件
平仓 → 自动检测 → 从文件中移除对应配置 → 清理文件
```

## 🔄 实现方案

### 1. 持仓变化检测与自动配置

#### 新持仓检测逻辑
```csharp
// AutoMonitorService.cs - 持仓扫描时
private async Task DetectPositionChangesAsync()
{
    var currentPositions = await _binanceService.GetPositionsAsync();
    var activePositions = currentPositions.Where(p => Math.Abs(p.PositionAmt) > 0).ToList();
    
    var existingStates = _stateService.LoadMonitoringStates();
    
    foreach (var position in activePositions)
    {
        var contractKey = GetContractKey(position.Symbol, position.PositionSide);
        
        // 🆕 检测新持仓
        if (!existingStates.ContainsKey(contractKey))
        {
            await CreateConfigForNewPosition(position);
        }
        else
        {
            // 🔄 更新现有持仓的实时数据
            await UpdateExistingPositionData(position, existingStates[contractKey]);
        }
    }
    
    // 🗑️ 检测已平仓的合约
    await CleanupClosedPositions(activePositions, existingStates);
}

/// <summary>
/// 为新持仓创建配置
/// </summary>
private async Task CreateConfigForNewPosition(PositionInfo position)
{
    var contractKey = GetContractKey(position.Symbol, position.PositionSide);
    
    // 📋 获取当前用户选择的基础配置
    var currentBaseConfig = GetCurrentSelectedBaseConfig();
    if (currentBaseConfig == null)
    {
        _logger.LogWarning($"⚠️ 无当前基础配置，跳过新持仓: {contractKey}");
        return;
    }
    
    // 🆕 基于基础配置生成新的监控状态
    var newState = _stateGenerator.GenerateFromPosition(position, currentBaseConfig);
    
    // 💾 保存到状态文件
    var existingStates = _stateService.LoadMonitoringStates();
    existingStates[contractKey] = newState;
    _stateService.SaveMonitoringStates(existingStates);
    
    _logger.LogInformation($"🆕 为新持仓创建配置: {contractKey} - 基于配置: {currentBaseConfig.Name}");
    
    // 📢 通知UI更新
    NotifyPositionConfigChanged(contractKey, PositionChangeType.Opened);
}

/// <summary>
/// 清理已平仓的合约配置
/// </summary>
private async Task CleanupClosedPositions(List<PositionInfo> activePositions, Dictionary<string, ContractMonitoringState> existingStates)
{
    var activeKeys = activePositions.Select(p => GetContractKey(p.Symbol, p.PositionSide)).ToHashSet();
    var statesToRemove = existingStates.Keys.Where(key => !activeKeys.Contains(key)).ToList();
    
    if (statesToRemove.Any())
    {
        foreach (var key in statesToRemove)
        {
            existingStates.Remove(key);
            _logger.LogInformation($"🗑️ 清理已平仓合约配置: {key}");
            
            // 📢 通知UI更新
            NotifyPositionConfigChanged(key, PositionChangeType.Closed);
        }
        
        // 💾 保存更新后的状态文件
        _stateService.SaveMonitoringStates(existingStates);
    }
}
```

### 2. UI界面数据源统一

#### 界面数据加载
```csharp
// AutoMonitorConfigWindowSimple.xaml.cs
private async Task LoadContractConfigsFromSingleSource()
{
    try
    {
        // 📍 唯一数据源：contract_monitoring_states.json
        var monitoringStates = _stateService.LoadMonitoringStates();
        
        // 🔄 清空UI集合
        await Application.Current.Dispatcher.InvokeAsync(() =>
        {
            ContractConfigs.Clear();
        });
        
        // 🎨 转换为UI显示模型
        foreach (var state in monitoringStates.Values.Where(s => s.IsActive))
        {
            var viewModel = ConvertStateToViewModel(state);
            await Application.Current.Dispatcher.InvokeAsync(() =>
            {
                ContractConfigs.Add(viewModel);
            });
        }
        
        _logger.LogInformation($"✅ 从统一状态文件加载配置: {ContractConfigs.Count} 个合约");
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, "❌ 从统一状态文件加载配置失败");
    }
}

/// <summary>
/// 将监控状态转换为UI视图模型
/// </summary>
private ContractConfigViewModel ConvertStateToViewModel(ContractMonitoringState state)
{
    var viewModel = new ContractConfigViewModel
    {
        ContractName = $"{state.Symbol}_{state.PositionSide}",
        Symbol = state.Symbol,
        PositionSide = state.PositionSide,
        BaseConfigName = state.BaseConfigName,
        IsEnabled = state.IsEnabled,
        CurrentPnl = state.CurrentUnrealizedPnl,
        PositionSize = state.CurrentQuantity,
        CurrentPrice = state.CurrentMarkPrice,
        
        // 🎯 状态转换
        BreakEvenStatus = ConvertExecutionStatusToText(state.BreakEvenConfig?.ExecutionStatus),
        BreakEvenTarget = state.BreakEvenConfig?.TriggerProfitAmount ?? 0
    };
    
    // 🔄 转换推仓状态
    for (int i = 0; i < (state.AddPositionConfig?.Tiers?.Count ?? 0); i++)
    {
        var tier = state.AddPositionConfig.Tiers[i];
        var key = $"Push{tier.TierIndex}";
        var status = ConvertExecutionStatusToText(tier.ExecutionStatus);
        viewModel.SetDynamicData(key, status);
    }
    
    // 🔄 转换保盈状态
    for (int i = 0; i < (state.ProfitProtectionConfig?.Tiers?.Count ?? 0); i++)
    {
        var tier = state.ProfitProtectionConfig.Tiers[i];
        var key = $"Profit{tier.TierIndex}";
        var status = ConvertExecutionStatusToText(tier.ExecutionStatus);
        viewModel.SetDynamicData(key, status);
    }
    
    return viewModel;
}
```

### 3. 配置保存统一

#### 配置变更保存
```csharp
// 用户编辑配置后保存
private async Task SaveConfigChangesToSingleSource(ContractConfigViewModel viewModel)
{
    try
    {
        // 📍 从统一状态文件读取现有状态
        var existingStates = _stateService.LoadMonitoringStates();
        var contractKey = viewModel.ContractName;
        
        if (existingStates.TryGetValue(contractKey, out var state))
        {
            // 🔄 更新配置数据（保留执行状态）
            UpdateStateFromViewModel(state, viewModel);
            
            // 💾 保存回统一状态文件
            existingStates[contractKey] = state;
            _stateService.SaveMonitoringStates(existingStates);
            
            _logger.LogInformation($"💾 配置已保存到统一状态文件: {contractKey}");
        }
        else
        {
            _logger.LogWarning($"⚠️ 未找到合约状态: {contractKey}");
        }
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, $"❌ 保存配置到统一状态文件失败: {viewModel.ContractName}");
    }
}

/// <summary>
/// 从UI视图模型更新监控状态（保留执行状态）
/// </summary>
private void UpdateStateFromViewModel(ContractMonitoringState state, ContractConfigViewModel viewModel)
{
    // 🔄 更新基础信息
    state.IsEnabled = viewModel.IsEnabled;
    state.BaseConfigName = viewModel.BaseConfigName;
    
    // 🔄 更新保本配置（保留执行状态）
    if (state.BreakEvenConfig != null)
    {
        state.BreakEvenConfig.TriggerProfitAmount = viewModel.BreakEvenTarget;
        // 🔒 保留执行状态：IsExecuted, ExecutionTime, ExecutionStatus 等
    }
    
    // 🔄 更新推仓配置（保留执行状态）
    if (state.AddPositionConfig?.Tiers != null)
    {
        foreach (var tier in state.AddPositionConfig.Tiers)
        {
            var key = $"Push{tier.TierIndex}Amount";
            if (viewModel.DynamicData.TryGetValue(key, out var amountStr) && 
                decimal.TryParse(amountStr, out var amount))
            {
                tier.TriggerProfitAmount = amount;
                // 🔒 保留执行状态
            }
        }
    }
    
    state.LastUpdateTime = DateTime.Now;
}
```

## 🎯 优化效果

### ✅ 解决的问题
1. **文件重复** - 只保留一个主要状态文件
2. **数据一致性** - 单一数据源，避免状态冲突  
3. **维护复杂性** - 简化文件管理，降低维护成本
4. **界面呈现** - 统一从一个文件读取，保证数据一致

### ✅ 新增功能
1. **自动配置生成** - 新持仓自动基于当前基础配置生成状态
2. **自动清理** - 平仓后自动从状态文件中移除
3. **实时同步** - 持仓变化实时反映到配置文件
4. **状态保护** - 配置更新时保留执行状态

### ✅ 用户体验改善
1. **配置即时生效** - 新持仓立即可用配置
2. **状态持久保留** - 执行状态不会因配置更改丢失
3. **自动管理** - 减少手动管理配置的工作量
4. **一致体验** - 界面显示与实际文件状态完全一致

这个优化方案彻底解决了文件重复问题，并且实现了您要求的自动配置管理功能！
