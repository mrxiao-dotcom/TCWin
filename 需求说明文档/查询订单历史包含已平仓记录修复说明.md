# 查询订单历史包含已平仓记录修复说明

## 问题描述

用户反馈查询订单历史时，有一些已经完全平仓的记录没有显示，不应该过滤掉。用户希望看到账户所有真实成交的记录，包括已经平仓的交易。

## 根本原因

原来的查询逻辑存在以下限制：

1. **只查询有持仓的合约**：只查询当前有持仓的合约历史订单
2. **兜底范围有限**：没有持仓时只查询最近5个委托合约
3. **遗漏已平仓合约**：完全平仓的合约不会被包含在查询范围内

这导致用户无法看到已经完全平仓的合约的成交记录。

## 修复方案

### 1. 扩大查询范围

修改查询逻辑，从多个来源收集需要查询的合约：

```csharp
var allSymbols = new HashSet<string>();

// 1. 添加当前有持仓的合约
var activeSymbols = Positions
    .Where(p => Math.Abs(p.PositionAmt) > 0.0001m)
    .Select(p => p.Symbol)
    .ToList();
foreach (var symbol in activeSymbols)
{
    allSymbols.Add(symbol);
}

// 2. 添加当前有委托的合约
var orderSymbols = Orders
    .Select(o => o.Symbol)
    .Where(s => !string.IsNullOrEmpty(s))
    .ToList();
foreach (var symbol in orderSymbols)
{
    allSymbols.Add(symbol);
}

// 3. 添加最近合约服务中的合约（这些可能是已平仓的合约）
var recentSymbols = _recentContractsService.LoadRecentContracts();
foreach (var symbol in recentSymbols.Take(10)) // 最多取10个最近合约
{
    allSymbols.Add(symbol);
}

// 4. 如果以上都没有，使用一些常见的合约作为兜底
if (!allSymbols.Any())
{
    var commonSymbols = new[] { "BTCUSDT", "ETHUSDT", "BNBUSDT", "ADAUSDT", "SOLUSDT" };
    foreach (var symbol in commonSymbols)
    {
        allSymbols.Add(symbol);
    }
    _logger.LogInformation("使用常见合约作为查询范围");
}
```

### 2. 智能查询策略

- **有持仓的合约**：查询更多历史记录（100条）
- **其他合约**：查询标准数量（50条）
- **并行查询**：同时查询所有相关合约，提高效率

### 3. 不过滤成交记录

确保只显示真实成交的订单，但不因为持仓状态而过滤：

```csharp
// 🔧 修复：不过滤任何成交记录，包括已平仓的交易
return orders?.Where(o => o.Status == "FILLED" || o.Status == "PARTIALLY_FILLED") ?? new List<OrderInfo>();
```

## 修复效果

### 查询范围扩大
- ✅ **当前持仓合约**：包含所有有持仓的合约
- ✅ **当前委托合约**：包含所有有委托的合约  
- ✅ **最近交易合约**：包含最近交易过的合约（最多10个）
- ✅ **兜底机制**：如果以上都没有，查询常见合约

### 记录完整性
- ✅ **已平仓记录**：能够显示已经完全平仓的合约的成交记录
- ✅ **历史交易**：包含用户所有真实成交的订单
- ✅ **时间排序**：按成交时间倒序排列，最新的在前面
- ✅ **数量限制**：最终显示最近20笔成交记录

### 查询效率
- ✅ **并行查询**：同时查询多个合约，提高查询速度
- ✅ **智能限制**：有持仓的合约查询更多记录，其他合约适量查询
- ✅ **去重处理**：使用HashSet避免重复查询相同合约

## 技术细节

### 修改的文件
- `ViewModels/MainViewModel.Data.cs` - 修改`CheckOrderHistoryAsync()`方法

### 关键改进点
1. **多源合约收集**：从持仓、委托、最近合约等多个来源收集
2. **HashSet去重**：避免重复查询相同合约
3. **智能查询量**：根据合约类型调整查询数量
4. **完整成交记录**：不因持仓状态过滤成交记录

### 查询逻辑流程
```
1. 收集当前持仓合约 → 添加到查询列表
2. 收集当前委托合约 → 添加到查询列表  
3. 收集最近交易合约 → 添加到查询列表
4. 如果列表为空 → 使用常见合约兜底
5. 并行查询所有合约 → 获取成交记录
6. 合并所有结果 → 按时间排序
7. 取最近20笔 → 显示给用户
```

通过扩大查询范围和改进查询策略，现在用户能够看到账户的完整交易历史，包括：

1. **当前持仓合约**的成交记录
2. **当前委托合约**的成交记录
