# 自动盯盘推仓保本止损价格计算修复说明

## 问题描述

用户发现了一个关键问题：

> 在推仓阶梯条件满足时，加仓时，生成了一个保本止损单，但我检查了他的计算止损价的结果不正确，并不是以加仓后的最新成本作为止损价，而是略高一些，这样很容易让加仓后的仓位被止损平仓。

## 问题分析

### 1. 原有计算逻辑（错误）

在`Services/AutoMonitorService.cs`中，有两处保本止损价格计算都存在问题：

#### A. 推仓后的保本止损计算（第452-457行）
```csharp
// ❌ 错误的计算方法
var stopQuantity = Math.Abs(updatedPosition.PositionAmt);
var bufferPerUnit = 1.0m / stopQuantity;
var newStopPrice = updatedPosition.PositionAmt > 0 
    ? updatedPosition.EntryPrice + bufferPerUnit
    : updatedPosition.EntryPrice - bufferPerUnit;
```

#### B. 普通自动保本止损计算（第339-343行）
```csharp
// ❌ 错误的计算方法
var quantity = Math.Abs(position.PositionAmt);
var bufferPerUnit = 1.0m / quantity;
var stopPrice = position.PositionAmt > 0 
    ? position.EntryPrice + bufferPerUnit
    : position.EntryPrice - bufferPerUnit;
```

### 2. 问题根源分析

#### A. 缓冲计算方式错误
```csharp
var bufferPerUnit = 1.0m / stopQuantity;
```

**问题**：
- 当持仓数量较小时，缓冲会变得非常大
- 例如：持仓0.001 BTC时，缓冲 = 1.0 / 0.001 = 1000，这是不合理的
- 当持仓数量较大时，缓冲又会变得很小

#### B. 不是真正的保本价格
- 使用固定金额缓冲（1U）分摊到每个单位
- 没有考虑不同价格合约的比例关系
- 导致止损价格偏离真实成本价

#### C. 具体示例
假设BTC价格50000U，持仓0.01 BTC：
- **错误计算**：缓冲 = 1.0 / 0.01 = 100U，止损价 = 50000 + 100 = 50100U
- **偏离程度**：比成本价高出0.2%，很容易被触发
- **真实影响**：加仓后的仓位很容易被错误平仓

## 修复方案

### 1. 使用百分比缓冲替代固定金额缓冲

#### 修复后的推仓保本止损计算
```csharp
// ✅ 正确的计算方法
// 🔧 修复：设置真正的保本止损，使用加仓后的最新成本价
var stopQuantity = Math.Abs(updatedPosition.PositionAmt);
var entryPrice = updatedPosition.EntryPrice; // 这是加仓后的最新成本价

// 使用很小的百分比缓冲（0.05%），确保真正保本而不会被轻易触发
var bufferPercentage = 0.0005m; // 0.05%
var newStopPrice = updatedPosition.PositionAmt > 0 
    ? entryPrice * (1 + bufferPercentage)  // 多头：成本价 + 0.05%
    : entryPrice * (1 - bufferPercentage); // 空头：成本价 - 0.05%
newStopPrice = Math.Round(newStopPrice, 4);

_logger.LogInformation($"💰 保本止损计算: 成本价={entryPrice:F4}, 缓冲={bufferPercentage * 100:F2}%, 止损价={newStopPrice:F4}");
```

#### 修复后的普通保本止损计算
```csharp
// ✅ 正确的计算方法
// 🔧 修复：计算真正的保本价格，使用百分比缓冲而不是固定金额缓冲
var quantity = Math.Abs(position.PositionAmt);
var entryPrice = position.EntryPrice;

// 使用很小的百分比缓冲（0.05%），确保真正保本而不会被轻易触发
var bufferPercentage = 0.0005m; // 0.05%
var stopPrice = position.PositionAmt > 0 
    ? entryPrice * (1 + bufferPercentage)  // 多头：成本价 + 0.05%
    : entryPrice * (1 - bufferPercentage); // 空头：成本价 - 0.05%
stopPrice = Math.Round(stopPrice, 4);

_logger.LogInformation($"💰 自动保本止损计算: 成本价={entryPrice:F4}, 缓冲={bufferPercentage * 100:F2}%, 止损价={stopPrice:F4}");
```

### 2. 关键改进点

#### A. 使用百分比缓冲
- **固定比例**：0.05%的缓冲，适用于所有价格水平的合约
- **合理范围**：既能防止手续费损失，又不会偏离成本价太多
- **一致性**：无论持仓大小，缓冲比例都是一致的

#### B. 基于真实成本价
- **推仓场景**：使用`updatedPosition.EntryPrice`，这是加仓后的最新成本价
- **普通场景**：使用`position.EntryPrice`，这是当前的成本价
- **准确性**：确保止损价格真正基于实际成本

#### C. 详细日志记录
- 记录成本价、缓冲比例、最终止损价
- 便于调试和验证计算结果
- 提高系统的可观测性

- **经过测试**：基于实际交易经验设定

### 2. 价格精度处理
- 使用`Math.Round(price, 4)`确保价格精度
