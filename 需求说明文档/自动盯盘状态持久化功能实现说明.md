# 自动盯盘状态持久化功能实现说明

## 问题背景

用户反馈了一个重要的问题：
> "关闭自动盯盘后，又重新启动，加仓信息又被重置，这样导致，又会重复执行1-4个加仓，这样是错误的，需要把信息在停止的时候保存在内存或文件里，重启后，要继承原来的这些信息，避免反复开仓"

## 问题分析

### 原有问题
1. **状态丢失**：自动盯盘停止后，所有执行状态都保存在内存中，程序重启后丢失
2. **重复执行**：重新启动自动盯盘时，系统不知道哪些阶梯已经执行过，会重复触发
3. **风险加大**：重复执行推仓阶梯会导致过度加仓，增加交易风险

### 具体场景
```
第一次运行：
12:22:34 - 触发推仓阶梯1，执行加仓
12:22:37 - 触发推仓阶梯2，执行加仓

停止自动盯盘 -> 重新启动

第二次运行（问题）：
12:25:00 - 重新检测到相同浮盈，再次触发推仓阶梯1，重复加仓 ❌
12:25:03 - 再次触发推仓阶梯2，重复加仓 ❌
```

## 解决方案

### 1. 创建持久化服务

新建 `AutoMonitorPersistenceService` 类，提供：
- **文件存储**：使用JSON格式保存到用户AppData目录
- **状态管理**：保存和恢复持仓档案和执行历史
- **自动清理**：定期清理过期数据

### 3. 技术实现

#### 3.1 AutoMonitorService 集成

```csharp
public class AutoMonitorService : IDisposable
{
    private readonly AutoMonitorPersistenceService _persistenceService;
    
    public AutoMonitorService(...)
    {
        // 初始化持久化服务
        _persistenceService = new AutoMonitorPersistenceService();
    }
}
```

#### 3.2 启动时恢复状态

```csharp
private async Task InitializePositionProfilesAsync()
{
    // 🔧 修改：先加载持久化的状态
    var persistedProfiles = _persistenceService.LoadPositionProfiles();
    
    foreach (var position in activePositions)
    {
        var key = GetPositionKey(position.Symbol, position.PositionSideString);
        
        // 如果持久化存储中有该持仓的档案，则使用持久化的数据（保留执行状态）
        if (persistedProfiles.ContainsKey(key))
        {
            var persistedProfile = persistedProfiles[key];
            // 更新实时数据，但保留执行状态
            persistedProfile.LastUpdateTime = DateTime.Now;
            persistedProfile.IsActive = true;
            
            _positionProfiles[key] = persistedProfile;
            _logger.LogInformation($"🔄 恢复持仓档案: {key} - 触发记录: {persistedProfile.TriggerRecords.Count}");
        }
    }
    
    // 加载执行历史
    var persistedHistory = _persistenceService.LoadExecutionHistory();
    _executionHistory.AddRange(persistedHistory);
}
```

#### 3.3 停止时保存状态

```csharp
public void StopMonitoring()
{
    // 🔧 新增：停止时保存状态到持久化存储
    try
    {
        _persistenceService.SavePositionProfiles(_positionProfiles);
        _persistenceService.SaveExecutionHistory(_executionHistory);
        _logger.LogInformation("💾 已保存自动盯盘状态到持久化存储");
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, "❌ 保存自动盯盘状态失败");
    }
}
```

#### 3.4 实时保存执行状态

```csharp
private void RecordTriggerExecution(PositionProfile profile, PositionInfo position, string triggerKey, string executionType, decimal currentPnl, bool success)
{
    // 记录到内存
    profile.TriggerRecords[triggerKey] = new TriggerRecord { ... };
    _executionHistory.Add(executionHistory);

    {
        _persistenceService.SavePositionProfiles(_positionProfiles);

    }
    catch (Exception ex)
    {
        _logger.LogError(ex, $"❌ 保存执行状态失败");
    }

```

## 数据管理

### 1. 存储位置
```
C:\Users\{用户名}\AppData\Roaming\BinanceFuturesTrader\AutoMonitor\
├── position_profiles.json    # 持仓档案
└── execution_history.json    # 执行历史
```

### 2. 自动清理策略
- **持仓档案**：清理超过24小时的非活跃档案
- **执行历史**：只保留最近7天的记录，最多1000条
- **启动时清理**：每次启动时自动清理过期数据

### 3. 数据安全
- **异常处理**：所有文件操作都有异常处理
- **数据验证**：加载时验证数据完整性
- **备份机制**：可以手动清空所有数据重新开始

## 兼容性说明

### 1. 向后兼容
- 现有的内存状态管理机制保持不变
- 持久化服务作为额外功能，不影响现有逻辑
- 如果持久化文件不存在，系统正常运行

### 2. 数据迁移
- 首次使用时自动创建数据目录
- 现有运行中的状态会在下次停止时自动保存
- 无需手动迁移或配置

### 3. 性能影响
- 文件操作异步进行，不阻塞主流程
- JSON序列化性能优秀，数据量小
- 只在状态变化时保存，不频繁写入

## 总结

通过实现状态持久化功能，我们解决了自动盯盘重复执行的关键问题：

### ✅ 解决的问题
1. **状态持久化**：执行状态保存到文件，程序重启后不丢失
2. **防重复执行**：已执行的阶梯不会重复触发
3. **数据安全**：异常处理和自动清理机制
4. **用户友好**：透明的日志输出和错误提示

### 🎯 核心价值
1. **风险控制**：避免过度加仓的风险
2. **状态一致性**：确保自动盯盘状态的连续性
3. **可靠性**：程序重启不影响交易策略执行
4. **可维护性**：清晰的数据结构和日志记录

现在用户可以安全地停止和重启自动盯盘功能，而不用担心重复执行推仓阶梯的问题。系统会智能地记住哪些阶梯已经执行过，确保交易策略的正确执行。
