# 分仓数量调整整数分拆优化说明

## 优化概述

本次更新优化了分仓止盈功能中的数量调整按钮（+/-），让它们遵循整数分拆规则：
- **前面的订单保持整数数量**
- **多余的数量（小数部分）统一给到最后一单**
- **确保总数量始终等于原始持仓数量**

## 优化前后对比

### 优化前的问题
```
原始数量：15.7 BTC，分拆成3单
初始分拆：第1单5个，第2单5个，第3单5.7个

点击第1单的"+"按钮（增加10%）：
第1单：5 + 0.5 = 5.5（产生小数）
第2单：5 - 0.25 = 4.75（产生小数）  
第3单：5.7 - 0.25 = 5.45（产生小数）

结果：所有订单都变成小数，不符合整数分拆原则
```

### 优化后的效果
```
原始数量：15.7 BTC，分拆成3单
初始分拆：第1单5个，第2单5个，第3单5.7个

点击第1单的"+"按钮（增加10%）：
第1单：5（整数，小数部分转移到最后一单）
第2单：5（整数，保持不变）
第3单：5.7（承担所有调整和小数部分）

结果：前面订单保持整数，符合整数分拆原则
```

## 核心算法实现

### 1. ApplyIntegerSplitRule 方法

这是整数分拆规则的核心实现方法：

```csharp
private void ApplyIntegerSplitRule(int targetIndex, decimal quantityChange)
{
    // 1. 调整目标订单数量
    var targetOrder = _splitOrders[targetIndex];
    var newQuantity = targetOrder.Quantity + quantityChange;
    targetOrder.Quantity = newQuantity;

    // 2. 平衡其他订单数量
    if (targetIndex != _splitOrders.Count - 1)
    {
        // 非最后一单：最后一单承担平衡调整
        var lastOrder = _splitOrders.Last();
        lastOrder.Quantity -= actualChange;
    }
    else
    {
        // 最后一单：其他订单平均承担调整
        var otherOrders = _splitOrders.Take(_splitOrders.Count - 1).ToList();
        var changePerOrder = -actualChange / otherOrders.Count;
        foreach (var order in otherOrders)
        {
            order.Quantity += changePerOrder;
        }
    }

    // 3. 应用整数分拆规则
    for (int i = 0; i < _splitOrders.Count - 1; i++)
    {
        var order = _splitOrders[i];
        var integerPart = Math.Floor(order.Quantity);
        var fractionalPart = order.Quantity - integerPart;
        
        if (fractionalPart > 0.000001m)
        {
            // 将小数部分转移到最后一单
            order.Quantity = integerPart;
            _splitOrders.Last().Quantity += fractionalPart;
        }
    }

    // 4. 验证总数量匹配
    var totalQuantity = _splitOrders.Sum(o => o.Quantity);
    var quantityDiff = _quantity - totalQuantity;
    if (Math.Abs(quantityDiff) > 0.000001m)
    {
        _splitOrders.Last().Quantity += quantityDiff;
    }
}
```

### 2. 数量调整按钮优化

#### 减少按钮（-）
```csharp
private void DecreaseQuantityButton_Click(object sender, RoutedEventArgs e)
{
    var order = _splitOrders[index];
    var originalQuantity = order.Quantity;
    var decreaseAmount = originalQuantity * 0.1m; // 减少10%
    var quantityDiff = -decreaseAmount; // 负数表示减少

    // 应用整数分拆规则
    ApplyIntegerSplitRule(index, quantityDiff);
    RefreshSplitOrdersUI();
}
```

#### 增加按钮（+）
```csharp
private void IncreaseQuantityButton_Click(object sender, RoutedEventArgs e)
{
    var order = _splitOrders[index];
    var originalQuantity = order.Quantity;
    var increaseAmount = originalQuantity * 0.1m; // 增加10%
    var quantityDiff = increaseAmount; // 正数表示增加

    // 检查其他订单是否有足够数量
    var totalOtherQuantity = _splitOrders.Where((o, i) => i != index).Sum(o => o.Quantity);
    
    if (totalOtherQuantity >= quantityDiff)
    {
        // 应用整数分拆规则
        ApplyIntegerSplitRule(index, quantityDiff);
        RefreshSplitOrdersUI();
    }
    else
    {
        MessageBox.Show("其他订单数量不足，无法继续增加此订单数量");
    }
}
```

## 详细调整逻辑

### 1. 调整非最后一单的情况

**场景**：调整第1单或第2单的数量

**处理逻辑**：
1. 调整目标订单的数量
2. 最后一单承担所有的平衡调整
3. 前面所有订单的小数部分转移到最后一单
4. 确保总数量不变

**示例**：
```
初始状态：第1单5个，第2单5个，第3单5.7个
点击第1单"+"（增加0.5）：

步骤1：第1单变为5.5个
步骤2：第3单减少0.5，变为5.2个
步骤3：第1单小数部分0.5转移到第3单
最终结果：第1单5个，第2单5个，第3单5.7个
```

### 2. 调整最后一单的情况

**场景**：调整最后一单的数量

**处理逻辑**：
1. 调整最后一单的数量
2. 其他订单平均承担平衡调整
3. 前面订单的小数部分转移到最后一单
4. 确保总数量不变

**示例**：
```
初始状态：第1单5个，第2单5个，第3单5.7个
点击第3单"+"（增加0.57）：

步骤1：第3单变为6.27个
步骤2：第1单和第2单各减少0.285，变为4.715个
步骤3：第1单和第2单的小数部分转移到第3单
最终结果：第1单4个，第2单4个，第3单7.7个
```

## 算法特点

### 1. 精度保证
- **总量恒定**：`Sum(所有订单数量) == 原始持仓数量`
- **小数精度**：所有计算保持6位小数精度
- **误差修正**：自动修正计算误差，确保精确匹配

### 2. 整数优先
- **前面订单整数化**：除最后一单外，所有订单都是整数
- **小数集中管理**：所有小数部分集中在最后一单
- **直观易懂**：整数订单更符合交易习惯

### 3. 安全边界
- **最小数量保护**：每个订单最少保持0.000001
- **数量不足检查**：增加数量前检查其他订单是否有足够余量
- **异常处理**：完善的错误处理和调试日志
