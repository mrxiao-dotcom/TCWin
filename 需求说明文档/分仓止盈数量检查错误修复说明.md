# 分仓止盈数量检查错误修复说明

## 问题描述

用户反馈：点击分仓止盈按钮后，提示"持仓数量不能为0"，但实际上选择的持仓单数量是正确的，弹出窗口显示的数量也是正确的。

## 问题分析

### 可能的原因

1. **构造函数时序问题**：构造函数中过早调用`GenerateSplitOrders()`，此时XAML控件可能还未完全初始化
2. **参数传递问题**：从MainViewModel传递到PartialProfitDialog的参数可能有问题
3. **数值精度问题**：decimal类型的比较可能存在精度误差
4. **控件状态问题**：某些控件在特定状态下可能返回异常值

### 诊断方法

#### 1. 添加详细调试日志

在构造函数中添加参数验证和调试信息：

## 修复方案

### 1. 构造函数参数验证

```csharp
public PartialProfitDialog(string symbol, string direction, decimal quantity, 
    decimal entryPrice, decimal unrealizedProfit, decimal currentPrice)
{
    InitializeComponent();
    
    // 在赋值给私有字段前进行参数验证
    if (quantity <= 0)
    {
        System.Diagnostics.Debug.WriteLine($"⚠️ 警告：传入的数量参数异常: {quantity}");
        MessageBox.Show($"传入的持仓数量参数异常: {quantity}\n请检查选中的持仓数据", 
            "参数错误", MessageBoxButton.OK, MessageBoxImage.Warning);
        return;
    }
    
    if (unrealizedProfit <= 0)
    {
        System.Diagnostics.Debug.WriteLine($"⚠️ 警告：传入的浮盈参数异常: {unrealizedProfit}");
        MessageBox.Show($"传入的浮盈参数异常: {unrealizedProfit:F2}\n分仓止盈要求当前必须有浮盈", 
            "参数错误", MessageBoxButton.OK, MessageBoxImage.Warning);
        return;
    }
    
    // 赋值给私有字段
    _symbol = symbol;
    _direction = direction;
    _quantity = quantity;
    _entryPrice = entryPrice;
    _currentPrice = currentPrice;
    _unrealizedProfit = unrealizedProfit;
    
    InitializeDialogData();
    
    // 延迟调用以确保所有控件都已初始化
    this.Loaded += (sender, e) => GenerateSplitOrders();
}
```

### 2. 改进GenerateSplitOrders检查

```csharp

            return;
        }
        
        // 继续其他逻辑...
    }
    catch (Exception ex)
    {
        // 异常处理...
    }
}
```

### 3. 调用时序优化

**问题**：在构造函数中立即调用`GenerateSplitOrders()`可能导致控件未完全初始化。

**解决方案**：使用`Loaded`事件延迟调用：

```csharp
// 构造函数中
InitializeDialogData();

// 延迟调用GenerateSplitOrders，确保所有控件都已初始化
this.Loaded += (sender, e) => GenerateSplitOrders();
```
