## 🔧 修复方案

### 1. API超时控制机制

为防止无限卡死，我添加了30秒超时控制：

**核心修复**：
- 使用 `Task.WhenAny` 实现超时竞争
- 30秒超时限制，防止无限等待
- 友好的超时错误提示
- 详细的超时诊断日志

**代码逻辑**：
```csharp
// 创建API调用和超时任务
var apiTask = _autoMonitorService.StartMonitoringAsync(config);
var timeoutTask = Task.Delay(TimeSpan.FromSeconds(30));

// 等待其中任一完成
var completedTask = await Task.WhenAny(apiTask, timeoutTask);

if (completedTask == timeoutTask) {
    // 超时处理
    throw new TimeoutException("API调用超时（30秒）");
} else {
    // 正常完成
    success = await apiTask;
}
```

### 2. 增强诊断系统

新增5个关键诊断点：

- `[PERFORM-16-1]` API超时控制已创建(30秒)
- `[PERFORM-16-2]` 开始超时包装的API调用  
- `[PERFORM-16-3]` 等待API调用或超时...
- `[PERFORM-16-TIMEOUT]` API调用超时(30秒) ← 超时标记
- `[PERFORM-TIMEOUT]` 确认为超时错误，不重试

### 3. 友好错误处理

超时时显示详细的错误信息：

```

🚨 可能原因：
• AutoMonitorService内部卡死
• 网络连接问题  
• API服务响应缓慢
• 内部死锁或阻塞

💡 建议：
• 检查网络连接
• 重启应用程序
• 检查API配置
```

## 🔍 技术细节

### 超时机制优势

1. **防止无限卡死** - 30秒后强制返回

- 保持系统状态一致性
