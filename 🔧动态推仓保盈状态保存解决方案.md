# 🔧 动态推仓保盈状态保存解决方案

## 💡 设计理念

**问题**：固定的推仓和保盈状态属性无法适应灵活的配置需求
- 推仓可能有10多次
- 保盈可以设置10级

**解决思路**：使用动态字典存储，根据文件中的实际配置来决定范围

## 🎯 核心设计方案

### 方案1：使用动态字典存储（推荐）

**修改 `ContractConfigViewModel` 类**：

```csharp
public class ContractConfigViewModel : INotifyPropertyChanged
{
    // 保留现有固定属性以保持向后兼容
    public string PushTier1Status { get; set; } = "-";
    public string PushTier2Status { get; set; } = "-";
    public string PushTier3Status { get; set; } = "-";
    public string PushTier4Status { get; set; } = "-";
    
    public string ProfitTier1Status { get; set; } = "-";
    public string ProfitTier2Status { get; set; } = "-";
    public string ProfitTier3Status { get; set; } = "-";
    
    // 🔧 【新增】动态状态字典
    /// <summary>
    /// 推仓状态动态字典 - 支持任意数量的推仓阶梯
    /// Key: 阶梯索引 (1, 2, 3, ...)
    /// Value: 状态 ("-", "√", "⚡")
    /// </summary>
    public Dictionary<int, string> PushTierStatuses { get; set; } = new Dictionary<int, string>();
    
    /// <summary>
    /// 保盈状态动态字典 - 支持任意数量的保盈阶梯
    /// Key: 阶梯索引 (1, 2, 3, ...)
    /// Value: 状态 ("-", "√", "⚡")
    /// </summary>
    public Dictionary<int, string> ProfitTierStatuses { get; set; } = new Dictionary<int, string>();
    
    // 🔧 【新增】获取推仓状态的便捷方法
    public string GetPushTierStatus(int tierIndex)
    {
        // 优先从动态字典获取
        if (PushTierStatuses.TryGetValue(tierIndex, out var dynamicStatus))
            return dynamicStatus;
            
        // 向后兼容：从固定属性获取
        return tierIndex switch
        {
            1 => PushTier1Status,
            2 => PushTier2Status,
            3 => PushTier3Status,
            4 => PushTier4Status,
            _ => "-"
        };
    }
    
    // 🔧 【新增】设置推仓状态的便捷方法
    public void SetPushTierStatus(int tierIndex, string status)
    {
        // 同时更新动态字典和固定属性
        PushTierStatuses[tierIndex] = status;
        
        // 向后兼容：同步到固定属性
        switch (tierIndex)
        {
            case 1: PushTier1Status = status; break;
            case 2: PushTier2Status = status; break;
            case 3: PushTier3Status = status; break;
            case 4: PushTier4Status = status; break;
        }
    }
    
    // 🔧 【新增】获取保盈状态的便捷方法
    public string GetProfitTierStatus(int tierIndex)
    {
        if (ProfitTierStatuses.TryGetValue(tierIndex, out var dynamicStatus))
            return dynamicStatus;
            
        return tierIndex switch
        {
            1 => ProfitTier1Status,
            2 => ProfitTier2Status,
            3 => ProfitTier3Status,
            _ => "-"
        };
    }
    
    // 🔧 【新增】设置保盈状态的便捷方法
    public void SetProfitTierStatus(int tierIndex, string status)
    {
        ProfitTierStatuses[tierIndex] = status;
        
        switch (tierIndex)
        {
            case 1: ProfitTier1Status = status; break;
            case 2: ProfitTier2Status = status; break;
            case 3: ProfitTier3Status = status; break;
        }
    }
}
```

### 方案2：动态状态同步方法

**修改 `SyncPushTierStatusFromUI()` 方法**：

```csharp
/// <summary>
/// 🔧 【动态修复】根据UI控件数量动态同步推仓状态
/// </summary>
private void SyncPushTierStatusFromUI()
{
    try
    {
        var comboBoxCount = _pushTierComboBoxes?.Count ?? 0;
        _logger?.LogCritical($"🔧【推仓同步】开始同步推仓状态，UI控件数量: {comboBoxCount}");
        
        // 🔧 【关键】清空现有的动态状态
        _editedConfig.PushTierStatuses.Clear();
        
        // 🔧 【动态同步】根据实际UI控件数量进行同步
        for (int i = 0; i < comboBoxCount; i++)
        {
            if (_pushTierComboBoxes[i]?.SelectedItem is ComboBoxItem item)
            {
                var tierIndex = i + 1; // 阶梯从1开始
                var newStatus = item.Tag?.ToString() ?? "-";
                var oldStatus = _editedConfig.GetPushTierStatus(tierIndex);
                
                // 🔧 【动态设置】使用便捷方法设置状态
                _editedConfig.SetPushTierStatus(tierIndex, newStatus);
                
                _logger?.LogCritical($"🔧【推仓同步】T{tierIndex}: {oldStatus} → {newStatus}");
            }
        }
        
        _logger?.LogCritical($"🔧【推仓同步】推仓状态同步完成，共同步 {comboBoxCount} 个阶梯");
    }
    catch (Exception ex)
    {
        _logger?.LogError(ex, "❌ 动态同步推仓状态失败");
    }
}
```

### 方案3：动态保存逻辑

**修改保存逻辑**：

```csharp
/// <summary>
/// 🔧 【动态保存】根据配置文件中的实际阶梯数量进行保存
/// </summary>
private void SaveContractConfigWithDynamicTiers(ContractMonitoringStateService stateService, string contractKey)
{
    try
    {
        var allStates = stateService.LoadMonitoringStates();
        if (!allStates.TryGetValue(contractKey, out var state))
        {
            _logger?.LogWarning($"⚠️ 未找到合约状态: {contractKey}");
            return;
        }
        
        // 🔧 【动态推仓保存】根据文件中的推仓阶梯数量
        var pushTiers = state.AddPositionConfig.Tiers;
        _logger?.LogCritical($"🔧【动态保存】文件中推仓阶梯数量: {pushTiers.Count}");
        
        foreach (var tier in pushTiers)
        {
            var tierIndex = tier.TierIndex;
            var newStatus = _editedConfig.GetPushTierStatus(tierIndex);
            var currentStatus = tier.ExecutionState == ExecutionState.Executed ? "√" : "-";
            
            if (newStatus != currentStatus)
            {
                _logger?.LogCritical($"🔧【动态保存】推仓T{tierIndex}状态变化: {currentStatus} → {newStatus}");
                
                if (newStatus == "√")
                {
                    tier.ExecutionState = ExecutionState.Executed;
                    tier.ExecutionTime = DateTime.Now;
                }
                else if (newStatus == "-")
                {
                    tier.ExecutionState = ExecutionState.NotTriggered;
                    tier.ExecutionTime = null;
                }
            }
        }
        
        // 🔧 【动态保盈保存】根据文件中的保盈阶梯数量
        var profitTiers = state.ProfitProtectionConfig.Tiers;
        _logger?.LogCritical($"🔧【动态保存】文件中保盈阶梯数量: {profitTiers.Count}");
        
        foreach (var tier in profitTiers)
        {
            var tierIndex = tier.TierIndex;
            var newStatus = _editedConfig.GetProfitTierStatus(tierIndex);
            var currentStatus = tier.ExecutionState == ExecutionState.Executed ? "√" : "-";
            
            if (newStatus != currentStatus)
            {
                _logger?.LogCritical($"🔧【动态保存】保盈T{tierIndex}状态变化: {currentStatus} → {newStatus}");
                
                if (newStatus == "√")
                {
                    tier.ExecutionState = ExecutionState.Executed;
                    tier.ExecutionTime = DateTime.Now;
                }
                else if (newStatus == "-")
                {
                    tier.ExecutionState = ExecutionState.NotTriggered;
                    tier.ExecutionTime = null;
                }
            }
        }
        
        // 保存到文件
        stateService.SaveMonitoringStates(allStates);
        _logger?.LogCritical($"🔧【动态保存】所有阶梯状态已保存");
    }
    catch (Exception ex)
    {
        _logger?.LogError(ex, "❌ 动态保存失败");
    }
}
```

### 方案4：动态验证逻辑

**修改保存确认验证**：

```csharp
/// <summary>
/// 🔧 【动态验证】根据实际阶梯数量进行保存结果验证
/// </summary>
private void VerifyDynamicSaveResults(ContractMonitoringStateService stateService, string contractKey)
{
    try
    {
        var savedStates = stateService.LoadMonitoringStates();
        if (!savedStates.TryGetValue(contractKey, out var savedState))
        {
            _logger?.LogCritical($"🔥【保存确认】❌ 重新读取时未找到合约: {contractKey}");
            return;
        }
        
        // 🔧 【动态验证推仓】验证所有推仓阶梯
        var pushTiers = savedState.AddPositionConfig.Tiers;
        _logger?.LogCritical($"🔥【保存确认】验证推仓状态，共 {pushTiers.Count} 个阶梯:");
        
        foreach (var tier in pushTiers)
        {
            _logger?.LogCritical($"🔥【保存确认】推仓阶梯{tier.TierIndex}状态: {tier.ExecutionState}");
            _logger?.LogCritical($"🔥【保存确认】推仓阶梯{tier.TierIndex}时间: {tier.ExecutionTime}");
        }
        
        // 🔧 【动态验证保盈】验证所有保盈阶梯
        var profitTiers = savedState.ProfitProtectionConfig.Tiers;
        _logger?.LogCritical($"🔥【保存确认】验证保盈状态，共 {profitTiers.Count} 个阶梯:");
        
        foreach (var tier in profitTiers)
        {
            _logger?.LogCritical($"🔥【保存确认】保盈阶梯{tier.TierIndex}状态: {tier.ExecutionState}");
            _logger?.LogCritical($"🔥【保存确认】保盈阶梯{tier.TierIndex}时间: {tier.ExecutionTime}");
        }
    }
    catch (Exception ex)
    {
        _logger?.LogError(ex, "❌ 动态验证失败");
    }
}
```

## 🎯 核心优势

### 1. **完全动态**
- 支持任意数量的推仓和保盈阶梯
- 根据实际配置文件内容决定处理范围
- 不再受固定属性数量限制

### 2. **向后兼容**
- 保留现有的固定属性
- 新旧数据结构可以并存
- 逐步迁移到动态方案

### 3. **灵活扩展**
- 推仓可以有10多次
- 保盈可以设置10级
- 根据业务需求自由调整

### 4. **智能适配**
- 自动检测UI控件数量
- 自动适配文件中的阶梯配置
- 无需手动配置范围
