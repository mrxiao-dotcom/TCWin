# 🎯 币安期货交易机器人 - 数据格式规范

## 📋 设计原则

1. **职责分离**：基础配置只存参数，状态文件只存状态
2. **结构简化**：减少不必要的嵌套和冗余字段
3. **状态清晰**：executionState 使用枚举值，含义明确
4. **扩展性强**：支持任意数量的推仓和保盈阶梯

## 🔢 ExecutionState 枚举值

| 值 | 名称 | 描述 | UI显示 |
|---|---|---|---|
| 0 | NotTriggered | 未触发 | - |
| 1 | Executing | 执行中 | 执行中 |
| 2 | Executed | 已执行 | √ |
| 3 | Failed | 执行失败 | ❌ |

---

## 🎯 数据流程

### 1. 初始化流程
```
基础配置 → 复制参数 → 创建状态文件 → 所有 executionState = 0
```

### 2. 监控执行流程
```
读取状态文件 → 检查 executionState → 
满足条件且状态=0 → 执行交易 → 
成功：状态=2，失败：状态=3 → 保存状态文件
```

### 3. UI刷新流程
```
读取状态文件 → 根据 executionState 显示UI状态 → 
0: "-", 1: "执行中", 2: "√", 3: "❌"
```

---

## ✅ 关键优势

1. **简单明确**：每个文件职责单一，结构清晰
2. **状态唯一**：只有统一状态文件存储执行状态
3. **易于调试**：状态变化路径简单，便于排查问题
4. **性能优良**：减少文件读写次数，提高响应速度
5. **扩展友好**：支持任意数量的阶梯配置

---

## 🔧 实现要点

1. **合约键值**：统一使用 `symbol_positionSide` 格式
2. **状态更新**：只在交易成功/失败时更新 executionState
3. **时间戳**：所有时间使用 ISO 8601 格式
4. **原子操作**：状态文件读写使用文件锁，确保数据一致性
5. **配置继承**：状态文件从基础配置继承参数，但独立管理状态
